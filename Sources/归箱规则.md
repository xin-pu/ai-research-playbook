# Sources 归箱规则

> 本文件规定外部资料进入 `Sources` 后落在哪里、长成什么形状、什么时候允许新建文件。每日采集任务和人工整理都以本文件为准；与本文件冲突的既有写法按本文件收敛。

## 1. 定位与适用边界

制定本规则的原因：按「一次采集产出一个文件」组织会让单日产出一堆十几行的摘要文件，且同一 URL 与同一事实在批量清单里被重复摘要。文件数量本身不是成本，**同一事实在多处各自演进**才是。

本规则适用：

- `Sources/` 下所有编号域目录（`00-rl` ~ `06-news`）。
- 每日自动采集任务的落盘动作。
- 人工研读公开资料后的来源登记。

本规则不适用：

- `knowledge-base/` 的正文组织方式（由 `AGENTS.md` 的正式正文模板约束）。
- `sandbox/` 的临时草稿、`outputs/weekly/` 的采集分析。
- 已经提升进 `knowledge-base` 的结论本身——本规则只管证据层。

## 2. 三层模型

| 层 | 载体 | 职责 | 数量约束 |
|---|---|---|---|
| 域 | `Sources/<NN-目录>/<唯一名称>导航.md` | 箱清单与原件清单，唯一且可辨识的目录级导航页。 | 每域恰好一个。 |
| 箱 | `主题-source.md` | 一个主题的全部证据，长期演进，只追加不新建。 | 一主题一个，不带日期。 |
| 证据块 | 箱内 `## E<编号> · 来源简称` 小节 | 单个来源的七字段登记。 | 一来源一块。 |
| 台账 | `Sources/update-log.md` | 流水：哪天动了哪个箱、加了几块、亮点。 | 不复制箱内内容。 |

**唯一归属原则**：一条证据只属于一个主箱。其他箱需要引用时写「见 `<箱名>#E<编号>`」，不复制其事实。这是防止重复摘要的主要机制。

### 2.1 导航页计数列

导航页只允许三种计数，每种都有唯一口径和一条复现命令：

| 列名 | 出现位置 | 口径 | 复现命令 |
|---|---|---|---|
| `箱数` | 总导航的域清单 | 该域内箱的篇数。 | `find <域> -name '*-source.md' \| wc -l` |
| `证据块` | 域导航的箱清单 | 箱内 `## E<编号>` 小节数。主题小节或登记表形态的箱没有证据块，一律记 `—`，**不得改用别的口径填数字**。 | `grep -c '^## E' <箱>` |
| `资讯条目` | `06-news` 箱清单 | 按日分节箱内的条目行数。 | `grep -c '^- \*\*' <箱>` |

原件数量不在箱清单里逐箱估算：箱内引用某份原件不代表该原件属于该箱，逐箱分配必然漂移。原件数按目录给出，口径是版本控制里的实际文件数，写在域导航末尾：`git ls-files <目录> | grep -vc '\.md$'`。

## 3. 箱的位置

- 主题需要同目录存放原件（PDF/图片/JSON）时：`Sources/<域>/<主题目录>/<主题>-source.md`。
- 纯笔记箱（无原件）时：直接放域根 `Sources/<域>/<主题>-source.md`，不为其新建子目录。
- 资讯类允许按时间成箱：`Sources/06-news/news-YYYY-MM.md`。时间就是这类资料的主题维度，按时间分箱不算碎片。
- 论文集中的主题（如某个会议的一批录用论文）允许 `Sources/<域>/<会议-slug>/<主题>-source.md`，原件同目录存放。

## 4. 归箱判定流程

采集到一份新资料后按顺序执行，前四步不需要主观判断：

1. **定域**：按采集优先级选一级域目录（`00-rl` 最高，其余按编号）。
2. **查域内导航页**：在目标域唯一命名的导航页箱清单里按主题关键词匹配。命中 → 进入第 5 步。
3. **查台账**：以 URL（arXiv 用不带版本号的 ID，如 `2510.01234`）和本地文件名为双主键查 `update-log.md` 与各箱。同源已登记 → 只在台账记一行「复查，无增量」，**不产生文件、不重复登记**。
4. **开箱门槛**：未命中任何既有箱时，满足以下任一条件才允许新建箱：
   - 已下载到 ≥ 1 份原件（PDF 等）；
   - 手上有 ≥ 3 条相互独立的来源；
   - 主题与所有既有箱处于不同层次（算法 / 模型 / 协议 / 工具链 / 评测），无法并入。

   三条都不满足 → 不建文件，只在台账登记标题与链接，等积累。
5. **落块**：在目标箱的证据索引表追加一行，并新增一个证据块，七字段填全。缺字段就写「公开资料未给」，不留空、不猜测。
6. **回写导航页**：更新该域导航页的箱行（块数、最近更新、状态）。有正式正文去向的，写在箱的「提炼去向」里，不写在导航页。

## 5. 箱的分裂与合并阈值

| 情况 | 动作 |
|---|---|
| 拟新建的独立文件不足 8 行，且同主题已有箱 | 禁止独立成篇，必须并为该箱的一个证据块。 |
| 箱超过 600 行或证据块超过 12 个 | 按子主题分裂成两个箱，并在两箱开头互相声明边界。 |
| 同域箱超过 8 个 | 重新审视主题划分是否过细，优先合并。 |
| 两个箱引用同一批 URL / 同一批 arXiv ID | 认定为一个主题，合并为一个箱，保留更早的箱名。 |

## 6. 证据块模板

```markdown
## E3 · GRPO 变体在长思维链推理上的稳定性

- 获取日期：2026-10-09
- 来源 URL：https://arxiv.org/abs/2510.01234
- 本地原件：`arxiv-2510.01234-grpo-variants.pdf`（无原件时写「—」）
- 适用范围：preprint，未经同行评议；覆盖 7B~32B 推理模型的离线策略 RL 对比；不覆盖多模态与在线部署场景。
- 证据等级：A
- 可提炼要点：
  1. ……
  2. ……
- 关闭条件：缺第三方复现；同组会议版录用或有公开复现后可关。
```

七个字段全部必填：获取日期、来源 URL、本地原件、适用范围、证据等级、可提炼要点、关闭条件。标签逐字写作 `- 获取日期：`…`- 关闭条件：`，冒号前不加修饰语——限定说明写在冒号之后。某字段的实质内容由块内分组明细承载时，该字段行写成指向明细的指针（`可提炼要点：分列下方……本块不重复汇总。`），不另写一份复述。

证据分级口径：**A** = 一手原件（论文原文、协议/spec 原文、官方文档与官方发布）；**B** = 深度分析、白皮书、综述、课程与教程材料；**C** = 新闻转述、榜单与二手摘要。**C 级不得作为定量结论来源**；需要量化数值时，必须回到 A 级原件。arXiv 预印本按 A 级登记，但「适用范围」必须注明 `preprint`。

禁止裸写 `TODO`、`TBD`、「待补充」。未完成项统一写成关闭条件：缺什么、从哪里补、什么条件下可以关。

**既有形态等价**：已有的箱若用 `### 3. 来源名` 序号小节，或用一行一来源、字段齐备的登记表表达同一含义，视为等价形态，保留原状，不为统一样式重排。新建箱与向既有箱追加来源时使用 `## E<编号>` 块。唯一硬约束是：同一来源不得在登记表和证据块里各写一遍。凡已采用 `## E` 块的箱，块内一律按 §6 的七个标签逐字写，供 §11 第 5 条核点。

## 7. 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 箱文件 | `<主题>-source.md`，kebab-case 全小写，**无日期前缀** | `grpo-rlhf-source.md` |
| 主题目录 | kebab-case，不用大写缩写目录名 | `neurips-2026/`，不用 `NeurIPS/` |
| arXiv 原件 | `arxiv-<id>-<slug>.pdf`（id 不带 vN） | `arxiv-2510.01234-grpo-variants.pdf` |
| 规范与官方文档原件 | `<来源>-<主题>-<slug>.<年>.<扩展名>` | `mcp-spec-streamable-http-2026.md` |
| 资讯箱 | `news-YYYY-MM.md` | `news-2026-10.md` |
| 域导航页 | 使用唯一的语义化名称，不使用 `index.md` 或 `README.md` | `00-rl/00-强化学习资料导航.md` |

历史命名 `YYYY-MM-DD-主题-web.md`、`source-summary.md` 已停用：日期是证据块属性，不是文件名属性。

## 8. 禁止项

- 禁止「一个来源一个文件」。
- 禁止在域或主题目录下再放第二个导航页；每层恰好一个唯一命名的导航页。
- 禁止在导航页里把空目录或无内容主题列为有效条目。未采集的候选主题放在导航页末尾的「候选主题（尚未采集）」一节，注明开启条件。
- 禁止把转换衍生物（`pdftotext` 的 `.txt`、缩略图、解包目录）纳入版本控制；需要时重新生成，已在 `.gitignore` 中排除。
- 禁止把同一 URL（或同一 arXiv ID）登记进两个箱。选一个主箱，其他位置用引用。
- 禁止在采集时修改 `knowledge-base/`；提升为正式结论是独立的人工动作。
- 禁止下载付费墙、登录墙内容，禁止保存模型权重、数据集整包与完整代码仓库镜像；这些只登记链接与元数据。

## 9. 并行采集的投递口

多个采集代理同时写同一域时，直接追加进同一个箱会产生写冲突。约定：

- 每个采集代理只写自己的投递文件 `Sources/<域>/.inbox/<run-id>-<主题-slug>.md`，内容就是一个或多个完整证据块。
- 主流程负责合箱：把投递块并入目标箱、重排 `E<编号>`、更新导航页与 `update-log.md`，然后清空已合并的投递文件。
- 采集代理不改导航页、`update-log.md`、`web-sources.md`。
- `.inbox/` 中的内容视为未入箱状态，不计入任何箱的块数；超过一周未合并必须显式关闭或删除。

## 10. 提升规则（Sources → knowledge-base）

- 箱不是结论。写入 `knowledge-base/solutions` 前必须说明来源材料或验证条件。
- 一个箱可以支撑多个正文，一条正文可以引用多个箱；引用关系记录在箱头的「提炼去向」和正文的「来源」两处。
- 提升完成后，箱内对应证据块标注状态「已提炼 → `03-02 §3.2`」，证据本身留在 `Sources`，不移动、不删除。
- 论文与规范只提炼结论、方法边界与可核对事实，不整篇复制原文；短引文标注论文 ID 与章节，正文层不搬运受版权保护的整段内容。
- 预印本的定量结论提升进正文时，必须同时写明「预印本，未复现」或补上复现记录。

## 11. 落盘后自检

每次归箱完成后核对六项：

1. **URL 主键查重**：除 `web-sources.md`（巡检入口清单）与 `update-log.md`（台账）外，一个 URL 在 `Sources` 内只能由一个文件登记；箱与导航页共用同一主键空间，同一箱内在「失效链接登记」表再次出现不算冲突。复现命令，输出必须为空：

   ```bash
   find Sources -name '*.md' ! -name 'web-sources.md' ! -name 'update-log.md' -print0 \
     | while IFS= read -r -d '' f; do
         grep -ohE 'https?://[^ )>"]+' "$f" | tr 'A-Z' 'a-z' | sed 's/[.,;]*$//' | sort -u
       done | sort | uniq -d
   ```

   命中即说明同一证据被两个文件登记：保留信息更全的那只为主箱，非主箱删掉「来源 URL」行，改写为一行 `主箱归属：……见 [箱名](相对链接)`，只留本箱自己的提炼点。
   不要用 `git ls-files` 的输出直接喂循环——中文文件名会被转义，路径查不到文件，命令会**静默返回空**（假通过）；查重一律用上面的 `find -print0`。
2. 目标箱的证据索引表行数与 `## E` 小节数量一致；主题小节形态的箱改核对该形态自己的条目清单，导航页对应列记 `—`。
3. 导航页计数与 §2.1 的口径一致：`证据块` 列逐个等于 `grep -c '^## E' <箱>` 的结果，`资讯条目` 列等于 `grep -c '^- \*\*' <箱>`，复现不了的数字就是虚标。
4. 整库一致性可以一次复核，不逐页人肉比对：
   `for f in $(find Sources -name '*-source.md'); do printf '%s %s\n' "$(grep -c '^## E' "$f")" "$f"; done`
   再把输出与所在域导航页的 `证据块` 列对照。
5. **证据块字段核点**：凡采用 `## E` 块的箱，七个字段标签的出现次数必须等于块数；不等即说明某块漏了字段，或标签被改名（见 §6）。复现命令，输出必须为空：

   ```bash
   for f in $(find Sources -name '*-source.md'); do
     e=$(grep -c '^## E' "$f"); [ "$e" -eq 0 ] && continue
     for k in 获取日期 "来源 URL" 本地原件 适用范围 证据等级 可提炼要点 关闭条件; do
       c=$(grep -c "^- $k：" "$f"); [ "$c" -ne "$e" ] && echo "$f: [$k] 出现 $c 次，E 块 $e 个"
     done
   done
   ```

   指针形态的字段行（`- 可提炼要点：分列下方……`）计入次数，因为标签还在；把内容直接写成 `- 一、……` 这类明细则不计，即判为缺字段。
6. `update-log.md` 顶部新增一条，指向被改动的箱，不复述块内容。
